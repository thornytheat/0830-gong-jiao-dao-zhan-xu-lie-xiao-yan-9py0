# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 晚到的人工确认到站可在“批次复核”面板补传：填写业务组、站点和到站时点后，系统按全部确认点重新核算，自动路径漏掉确认点时会改用覆盖确认点的达标路径。
6. 确认点时间与站序冲突时，业务组显示“确认点冲突暂缓”，整批不可签发；撤回冲突确认点后自动重算，恢复达标即可签发。
7. 撤回与签发若同时提交，以版本号为准：先生效的操作推进版本，旧版本号的操作返回 409，刷新后重试。
8. 导出复核证据并保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
